## 2. 技术债清单

### 2.1 高优先级（建议优先处理，但本次不执行）

**H1　HTTP 层零单元测试 `[确认]`**
`app.py:291-665` 的 `make_handler` 是闭包工厂，内含 14 个 GET/POST 分支。`lite/tests/` 全库 grep `import app|make_handler|do_GET|do_POST` **零命中**。新增的 `/api/note`（0.2.11）也只有 `devtools/smoke_ui_note.py` 冒烟，没有单测。
影响：路由状态码、chunked 读取、`OPTION_LOCK` 并发、更新回滚链路没有回归网。
建议：把 handler 抽成可注入类，补路由级测试（不需要真实 maa）。风险：中等重构量。
复核：`grep -rn "import app\|make_handler\|do_GET" lite/tests/`

**H2　Agent 存活探测异常被当成「还活着」 `[确认]`**
`lite/session.py:745-751`：`alive = True` → `try: alive = bool(agent_check())` → `except Exception: alive = True`。
影响：Agent 探针自身抛异常时，任务继续跑，表现为「没有日志的卡住」，事后无法归因。这是真正可能掩盖故障的一处。
建议：异常时记 warn，并把默认值改为 `False`（或保留 `True` 但至少限制连续次数）。风险：探针偶发抖动会触发误重启，需配合 `test_session_*` 验证。
统计：`lite/` 下 `except Exception|BLE001` 约 80 处（session ~30、run_service ~20、downloader ~10），大多是「后台便利功能」的静默降级，可分级处理，不建议一次性全改。

**H3　6 个 GitHub workflow 全是上游遗留，Lite 测试从未在 CI 跑 `[确认]`**
`.github/workflows/check.yml:36` 调 `check_resource.py`、`install.yml:39,41,63,68,108` 调 `tools/ci/tests`、`release_meta.py`、`setup_embed_python.py`、`install4release.py`——这些文件在本仓库**全部不存在**。6 个 workflow 无一处引用 `devtools/run_tests.py` 或 `lite/tests`。
影响：push/PR 时 254 项测试、`app.py --selftest`、`build_release.py` 一条都不跑。
建议：新增一个只跑 `run_tests.py` 的 Lite CI；上游 workflow 归档或标注「上游同步用」。风险：删除会改变上游同步策略，需确认它们是否来自 submodule 且有意保留。

**H4　两套 UI 复制了 6 组业务判断，状态枚举已漂移 `[确认]`**
逐字重复的位置（`lite/ui/index.html` ↔ `MainWindow.xaml.cs`）：状态中文映射、状态颜色、勾选默认逻辑（连注释都相同）、全选/反选、开始按钮计数与三串文案、任务列表渲染 + 签名 diff。
漂移：`app.py:30` 的 `TASK_STATES` **缺 `skipped_no_resource`**，而 `index.html`、`MainWindow.xaml.cs:811`、`run_service.py` 都有该状态；`/api/meta` 导出的 `runStates/taskStates/startupActions` 全局 grep **没有任何客户端消费**（WPF `LoadMetaAsync` 只读 `version`）。
影响：任一业务口径（如 0.2.4 的「未领取」）必须改两处；枚举导出形同虚设。
建议：短期让两 UI 消费 `/api/meta` 的字典；长期若 `--legacy` 退役，删 `index.html`（1028 行）+ 契约兼容层。风险：退役决策见「待确认」。

**H5　两套 `start-lite.bat` 编码互斥，`--legacy` 已不在发布包 `[确认]`**
根目录 `start-lite.bat`：1079 字节、**GBK**、39 行全 CRLF、含 `:legacy` 分支和硬编码 `net10.0-windows` 路径；`devtools/build_release.py:35-76` 的 `START_BAT` 模板：**UTF-8 + `chcp 65001`**、纯 ASCII 守卫块、**无 `--legacy`**。`MANIFEST.md:18` 写的是「GBK + CRLF」。`test_launcher_guard.py` 测的是模板，不是根目录那份。

### 2.3 明确「不建议动」的结论（避免误清理）

- `maafw==5.6.0`：`session.py:62-66` 注释说明 `ContextEventSink` 事件行为依赖该版本，看门狗/死循环守卫建立在它之上；升级会破坏已验证行为。
- `.NET framework-dependent` + WPF 守卫块：用户已明确否决自包含（343MB → 410MB），守卫是必要兜底。
- `lite/http_body.py` 的 chunked 支持 + 9 项测试：触发它的 `JsonContent.Create` 客户端已不存在，现为**防御性兼容**；删掉后第三方按 chunked 调用会静默得到 `{}`（正是 11-05 的历史故障）。建议保留并标注。
- `settings.py` 的 camelCase/snake_case 双写：HTML 控制台确实消费 snake_case 字段，**当前不可删**；退役 `--legacy` 后才可整块移除。
- `agent/custom/` 里的成段注释旧实现：属上游代码，Lite 侧不主动清理。
- 正面结论：静态 import 图交叉验证显示 `lite/` 下**没有完全未被引用的模块**，也没有「只被测试引用」的生产函数；`devtools/` 21 个 `.py` 都是独立 CLI（无自动化调用入口，但属人工排障工具，不能据此判定为死代码）。
