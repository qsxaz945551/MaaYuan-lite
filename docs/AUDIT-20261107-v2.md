## 3. 技术债清单

### 3.1 高优先级

**T1　HTTP 层零单测，而它是最大单块 `[确认]`**
`app.py:291-665 make_handler`：**375 行、71 个分支**，内含 14 个路由；`do_POST` 单独 173 行 / 42 分支。`lite/tests/` 搜 `import app|make_handler|do_GET|do_POST` 零命中。0.2.11 新增的 `/api/note` 也只有 `devtools/smoke_ui_note.py` 冒烟。
影响：状态码、请求体解析、`OPTION_LOCK`、更新回滚链路无回归网。
建议：先把 handler 拆成独立类（顺带解决 T11），再用 `ThreadingHTTPServer` 起临时端口的路由测试。
风险：中等重构；`/api/*` 契约不能变。

**T2　Agent 探针异常 = 「还活着」 `[确认]`**
`lite/session.py:745-751`：`alive = True` → `try` → `except Exception: alive = True`。
影响：探针自身故障时任务继续跑，表现为「没有日志的卡住」。
建议：异常时 `_log(..., "warn")`，并把默认值改 `False`（或连续 N 次才判定）；用 `test_session_*` 回归。
风险：探针抖动可能误重启 Agent。

**T3　CI 与项目脱节 `[确认]`**
6 个 workflow 调用的 `check_resource.py`、`tools/ci/*`、`install4release.py`、`android/prepare.py` **全部不存在**；无一处调用 `devtools/run_tests.py`。
影响：254 项测试、`--selftest`、打包脚本在 CI 里一次都不跑。
建议：新增一个只跑 `run_tests.py` 的 workflow；上游 6 个标注「上游同步用」或归档。

**T4　核心模块无直接测试（上一版未列）`[确认]`**
按模块名与测试文件映射：`adb_finder`、`apply_scope`、`guards`、`selftest`、`source_manifest`、`version` **六个模块无直接测试**。
其中 `source_manifest` 被 `downloader`、`updater`、`update_applier`、`devtools/sync_repo.py` 依赖，负责 manifest 读写与模型校验——更新链路的地基，却没有单测。
建议：优先给 `source_manifest` 补「缺字段 / 版本漂移 / 模型清单不全」三类用例；`guards`（`NodeRepeatGuard`）也值得补。

**T5　两套 UI 重复 + 枚举漂移 `[确认]`**
- 文案重复量化：C# 有 104 条中文字面量、HTML 45 条，**26 条逐字相同**（占 HTML 的 58%），包括「开始任务（N）」「先勾选要执行的任务」「收到停止请求，正在结束当前任务……」等。
- 逻辑重复 6 组：状态映射、状态颜色、勾选默认值、全选、按钮计数、列表渲染 + 签名 diff。
- 漂移：`app.py:30 TASK_STATES` 缺 `skipped_no_resource`；`/api/meta` 导出的 `runStates/taskStates/startupActions` **无任何客户端消费**。
建议：短期让两 UI 读 `/api/meta` 的字典（顺带补上缺失状态）；长期随 `--legacy` 退役删 HTML。

**T6　文档过时到会误导复核 `[确认]`**
`HANDOFF-20261107.md`（active=0.2.2）、`PROJECT-REPORT.md`（0.2.3 已切 active，但 W12–W20 又写到 0.2.11）、`LITE.md:88` 与 `:331` 自相矛盾、`代码结构自查报告.md`（49 项测试 / app.py 430 行）、`README.md`（上游原版）、`api-contract.md`（0.2.0）。
